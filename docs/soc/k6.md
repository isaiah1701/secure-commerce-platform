# Bounded SOC traffic

Run only against the owned commerce lab. Each request carries a bounded,
traceable `X-SOC-Scenario-ID`, which is emitted as `simulation_id` in
`ContainerAppConsoleLogs_CL.Log_s`.

```bash
k6 run -e BASE_URL=https://shop.platf0rm.site \
  -e SCENARIO=auth-lockout \
  -e SCENARIO_ID=soc-auth-lockout-20261030T101309Z \
  -e TEST_USER=<owned-lab-account>@platf0rm.site \
  -e TEST_PASSWORD='<lab-password>' \
  -e RATE=1 -e DURATION=30s \
  soc/k6/scenarios.js
```

Supported scenarios are `auth-lockout`, `privilege-probe`, `suspicious-api`,
`auth-rate-limit`, and `multi-event`. The script uses at most two VUs and one
iteration per second. The rate-limit scenario sends twelve bounded login
requests within each iteration to exercise the configured application control;
do not increase its duration or rate. Set `KILL_SWITCH=true` to disable
requests immediately. Use designated test credentials only; never use real
user accounts.

The scenario identifier is the pivot for Log Analytics:

```kusto
ContainerAppConsoleLogs_CL
| where TimeGenerated > ago(1h)
| extend payload = parse_json(Log_s)
| where tostring(payload.simulation_id) == "<scenario-id>"
| project TimeGenerated, payload
| order by TimeGenerated asc
```
